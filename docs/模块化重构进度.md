# idle-awakening 模块化重构进度

## 本阶段目标

- 所有新增用户可见内容使用简体中文。
- 不直接重写 6 MB 生产 bundle，先建立可维护的源码边界。
- 将 UI、命令载荷、Worker 通信从旧 bundle 的一次性构建产物中逐步抽离。

## 目录

- `modules/ui/`：可独立维护的 UI 模块。
- `modules/commands/`：命令载荷构造。
- `modules/worker/`：Worker 通信边界。
- `modules/bootstrap.js`：模块化增强入口。
- `tests/`：Node smoke/unit tests。

## Bundle 拆分策略

当前仓库只有生产 bundle、汉化脚本和静态资源，没有提交原始 `src/` 与构建配置。因此本阶段不对 6 MB bundle 做不可逆的人工反编译。

迁移顺序：

1. 先用模块化入口承接新 UI。
2. 将 Worker 调用统一迁移到 `GameWorkerClient`。
3. 将旧代码中的 command payload 构造逐项替换为 `createCommandPayload`。
4. 恢复/补齐源码与构建配置后，再删除 Babel helper 重复产物。
5. 最后建立 Browser E2E，并以测试结果作为 bundle 删除旧实现的门槛。

这样可以保持现有游戏可运行，同时让新增功能不再继续堆进 bundle。
