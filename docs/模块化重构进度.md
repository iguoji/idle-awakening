## 当前仓库事实

生产 `bundle.js` 是 webpack development/eval 构建产物，并保留 `sourceURL` 中的原始模块路径，例如 `src/index.js`、`src/App.js`、`src/general/client.js`、`src/worker/main.worker.js`。但仓库没有对应 `src/` 原始源码目录，因此直接人工重写整个 bundle 会破坏可重复构建能力。

## 已建立的迁移边界

- `modules/ui/`：中文维护 UI。
- `modules/commands/`：统一 command payload。
- `modules/worker/`：Worker 通信适配层。
- `tests/`：Node smoke/unit tests。
- `tests/e2e/`：浏览器行为测试。
- `scripts/audit-bundle.mjs`：Babel helper 持续审计。

## 下一阶段

1. 获取/恢复原始 `src/` 与 webpack/Babel 构建配置。
2. 优先迁移 `src/worker/main.worker.js` 与 `src/general/client.js` 到模块化 Worker 边界。
3. 将真实业务 command 调用逐项替换为统一 payload builder。
4. 用 E2E 作为删除旧 UI/旧通信实现的门禁。
5. 重新构建生产 bundle，确认 Babel helper 数量下降后再删除旧 helper。

当前策略是：**先建立可验证的模块边界，再删除旧实现**，避免为了“拆 bundle”而破坏游戏运行。
